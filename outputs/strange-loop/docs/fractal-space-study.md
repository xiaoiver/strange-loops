# 分形空间原型

2026-10-26，独立验证「立方体孔洞连接一个可持续向内漫游的空间」。原型入口为 `fractal-preview.html`，本页不读写章节存档，也不包含在官网发布包中。2026-10-26，已将共用数学与着色器移到 `src/fractal-*`，接入正式第三章；本页继续作为独立研究入口。

## 运行

```sh
npm install
npm run fractal:build
npm start
```

访问 `http://127.0.0.1:4173/fractal-preview.html?lang=zh`；英文使用 `?lang=en`。若已有服务在运行，只需构建并刷新。修改着色器或控制器后重新运行 `npm run fractal:build`。生成的 `dev/fractal-preview.js` 被 Git 忽略。

## 操作

- 点击「走进孔洞」，约 14 秒完成入口过渡，随后以每秒 6 个内部单位持续前进，不再到达一个停止播放的终点。
- 行进中可以暂停，再次点击继续；「回到入口」或 Esc 直接重置位置与视角。入口结束时的速度与巡航速度衔接，暂停后继续会缓慢加速。
- 下方滑杆只控制外部到内部的入口过渡，不表示无限漫游的总进度。拖动画面环视；滚轮或画布获得焦点后的上下方向键可手动前进、后退，并暂停自动行进。空格暂停或继续。
- 中英文切换保留位置与视角。减少动态偏好下，入口直接到达内部，此后主按钮改为「向前一步」，每次前进 4 个内部单位；手动滑杆仍可逐步探索。
- 页面不自动行进；静止时不持续重绘。后台暂停，返回前台不跳过整段行进。

## 空间构造

外部是一只三次细分的门格海绵，使用有限 CSG 距离界限，在 GPU 上直接渲染。地面为解析平面；表面粗糙、哑光，使用原创程序化水泥云斑与细小对拉孔。

前方中央孔洞是一道尺度门户：外部坐标通过该开口映射到 8 倍内部坐标。射线穿过孔洞后，接着对内部距离场行进，而非显示预录视频或背景图片。相机越过同一平面时使用相同映射，返回路径也沿用该规则。

内部由在空间中重复的门格距离场组成，各纵深层具有不同倾角和尺度，通道的中心线缓慢弯曲。相机随中心线前进，同时保持自身竖直方向，梁柱、地面和开口在远处形成交错朝向。这些变化由所在位置决定，不随时间自行转动，暂停后空间也会静止。距离场在视觉范围内重复，分形细节有限迭代；并非无穷精度或真正生成无限个网格。

每跨越 36 个单位，就将相机重新定位到局部坐标区间 `[-18, 18)`，同时补偿结构倾角、尺度和曲线的相位。相位始终保持在 `[0, 2π)`，GPU 不接收持续增大的世界坐标。重置前后的几何、材质坐标及相机方向保持一致；CPU 只复用一个固定大小的行进状态，不保存沿途轨迹。

## 渲染与边界

- Three.js WebGL2 全屏三角形，自定义 GLSL Ray Marching；程序化几何与着色器为本项目原创代码。
- 法线来自距离场采样，光照包含粗糙介电 GGX/Schlick 响应、单个方向光、距离场软阴影与环境遮蔽；远处用距离雾建立尺度。曝光与明暗在内部单独校准。
- 光照、AO、阴影在此着色器内计算。独立研究页不与角色网格、Three.js 阴影贴图或 GTAO 合成。正式第三章使用实体孔洞窗口，并在穿入后切换内部渲染管线；外部角色留在展厅，内部不重复套用 GTAO。
- 射线最大距离 185，循环上限 144 次；桌面实际最多 136 步、4 层分形，窄屏最多 100 步、3 层。距离、迭代、几何体和纹理数量都不随漫游时长增加。
- 桌面约 86 万、手机约 39 万像素预算；行进中持续低帧率会适度降低渲染比例，最低为原预算的 62% 线性比例。未承诺所有移动设备达到固定帧率。
- 不需要 Blender 资产，也没有新增外部贴图、录音或运行时网络依赖。

数学背景可参考 [IIT 的 Karl Menger 介绍](https://www.math.iit.edu/Menger/menger_old.html)；距离估计与分形形状渲染可参考 [Purdue：Shape Modeling with Fractals](https://web.ics.purdue.edu/~tmcgraw/papers/mcgraw_fractal_2014.pdf)。这些是背景资料，原型没有复制示例项目的着色器源码或美术资产。

## 验证

单元检查入口轨迹的连续性和反向采样、不同屏幕与 DPR 的填充预算、一百万帧行进后的坐标与相位边界、跨区间时场函数相位和相机方向的一致性、手动前进后退，以及入口速度与巡航的衔接。发布检查排除原型 HTML 与全部 `dev/` 文件。

持续运行约两分钟后，桌面视口 1048 × 954，实际渲染 972 × 885，采样均为约 60 fps，帧间隔第 95 百分位 16.8–17.5 ms；17 次坐标重置后，资源仍为 1 个几何体、0 个纹理、1 个着色器程序。帧率来自前台 `requestAnimationFrame` 间隔，是本机浏览器表现，不是 GPU 计时或实体手机基准。资源数来自 Three.js 的 renderer.info，能验证渲染资源不沿途累积，不等同于完整浏览器堆内存分析。

独立原型阶段构建和 110 项测试通过。正式接入后的当前验证见 [第三章验收](chapter-03-verification.md)。浏览器检查包含着色器编译、外部视角、门户边界、内部远近层次、持续行进、暂停、返回与滑杆、中英文切换。静止状态帧计数不持续增加。桌面和手机视口检查不等同于实体手机的 GPU 性能测试。
